Content Security Policy (CSP) como segunda línea de defensa Aunque apliques escape contextual en todas tus plantillas, la arquitectura defensiva moderna exige una segunda barrera: la cabecera Content-Security-Policy (CSP) . CSP le indica al navegador qué fuentes de contenido están autorizadas. Incluso si un desarrollador cometiera un error y olvidara escapar una variable en una página, una política CSP bien diseñada impide que el navegador ejecute scripts inline ( o manejadores onload= , onerror= ) y prohíbe enviar datos hacia dominios externos desconocidos ( connect-src 'self' ). Directiva CSP Valor seguro recomendado Qué restringe en el navegador default-src 'self' Solo el propio origen por defecto Política base para cualquier recurso no especificado por separado. script-src 'self' (o 'nonce-...' ) Prohíbe scripts inline arbitrarios y dominios terceros Solo ejecuta archivos .js del propio origen o bloques con el nonce criptográfico generado por petición. object-src 'none' Desactiva plugins heredados Bloquea elementos
